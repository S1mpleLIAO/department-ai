# 独立验收：升级检查、存储管理、宿主权限收敛
2026-10-30。用户已授权在独立环境实施，保留会话和文件，不升级 Harness、不影响生产。

## 实施边界
- 复用当前 0.1.5-rc.1、统一身份、用户/空间实例和原生附件；不引入 dsh-login。
- 无数据库迁移、不改业务 REST；新增运维 CLI 和启动前检查。
- 兼容基线仅覆盖源码/包元信息与我们接入的模块；不读取或哈希大型构建产物。版本/接口/插件发生变化须先在候选环境重新验证，不能自动重写基线放行。
- 每账号跨空间合计默认 512 MiB、10000 文件，宿主保留 2 GiB。按现有目录计量，不复制文件。上传和生成串行准入；已超额允许读取/下载，禁止新增写入，不删除既有文件。这是应用层准入配额，不承诺正在执行的 DSH 写入等价内核硬配额。
- 清理只针对新版打标的失败报销临时目录，默认 dry-run；只有相应用户实例停止、无报销执行器、超过 24h 且无符号链接时可清理。会话、附件、工作区、个人设置永久排除。
- 宿主验收服务改为专用非 root 账号；不加入 docker 组、不开放任意 sudo。root 拥有的固定助手仅允许验收命名空间下的容器查询、停止和两种固定运行配方。禁止生产容器、任意挂载、host 网络、特权模式及 Docker exec。
- 现存验收数据仅调整必要的属主/访问权限，不改内容。源代码、虚拟环境、固定助手仍由 root 控制。数据库管理员凭据不授予应用账号。
- 部署前确认无正在运行的个人实例，停止的仅是当前独立 supervisor；生产端口/PID 前后对照。先验证受限助手与隔离、再切换验收服务。
- 报销生成仍使用已发布技能和独立受限执行器。不能借此开放任意 shell 或未审核技能。

## 验证
兼容版本/源码/缺插件故障拦截；配额并发及跨空间合计、超额保留、临时清理保护；宿主 helper 恶意参数拒绝、非 root 无 Docker/生产秘密访问；原生上传/报销/下载、会话与配置持久化回归。结果补记于本文。

## 实际部署边界
- 仅独立验收目录及 3181–3184；现网 3080/3081、现网数据库和 Harness 构建不变。
- 部门服务：systemd `department-identity-acceptance.service`，UID/GID 10001，NoNewPrivileges=true，CapabilityBoundingSet 为空；没有 Docker 组或 sudo 规则。
- 固定管理服务：`department-identity-container-broker.service`。仅 Unix Socket，校验 SO_PEERCRED 的 UID 10001；root 组件仍存在，但只接受固定配方和验收容器命名空间。
- 个人目录父级与挂载入口由 root 控制，工作区/配置/上传内容仍可写。禁止将个人挂载入口替换成宿主路径的符号链接。
- 已有授权版本记录保留原文件，首次启动时迁移副本到个人 `.control`；历史会话和用户文件不迁走、不清除。
- 不启用定时清理；Docker 容器日志轮转上限 10 MiB × 2，用户文件通过写入准入管理。
- `deploy/identity/prepare-acceptance-host.py` 仅安装固定助手和已验收的 systemd 单元，不重启、不迁移数据；需要在现有独立环境由管理员运行。它不是正式上线或新服务器通用部署脚本。

## 配置项
| 配置 | 当前值 | 含义 |
|---|---:|---|
| DEPARTMENT_AI_USER_STORAGE_MIB | 512 | 同一账号跨公司空间合计逻辑文件大小 |
| DEPARTMENT_AI_USER_FILE_LIMIT | 10000 | 同一账号文件数量 |
| DEPARTMENT_AI_MIN_FREE_MIB | 2048 | 宿主至少保留的可用磁盘余量 |
| DEPARTMENT_AI_MAX_INSTANCES | 4 | 个人运行实例上限，沿用排队和空闲回收 |

这些是应用层写入准入限制，不是文件系统硬配额；已在运行的任务、会话日志仍可能继续写入。磁盘报告不会读取或哈希文件内容。超额不删除任何已有会话、文件或配置。
