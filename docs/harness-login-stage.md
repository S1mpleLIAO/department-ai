# Harness 统一登录接入契约

> 当前状态（2026-10-29）：统一登录、权限、审核和个人AI已接入独立人工验收环境；容量上限为4，具备排队、空闲回收和启动恢复保护。以下按阶段保留历史记录，早期“2个实例”“临时环境已停止”等表述不代表当前验收部署。当前入口与限制见[人工验收指南](identity-human-acceptance.md)，最新检查见[人工验收前检查](identity-preacceptance-readiness.md)。

本阶段仅在 identity-access-20261028 独立环境实施；禁止使用现网 home、3080、数据库、Nginx 或共享技能目录。

## 边界与接口

- 新增 assistant.use、skills.use 权限，默认权限组不自动扩权。知识和流程读取还需各自 read 权限。skills.use 与查看/修改源码相互独立。
- POST /api/assistant/entry 验证部门会话、CSRF、空间和 assistant.use，生成 60 秒一次性随机票据；票据绑定登录会话、用户、空间及配置的 AI origin。浏览器 POST 到固定 origin 的 /bootstrap，交换专用 HttpOnly Cookie；不得使用 URL token 或透传 Harness Cookie。
- AI 网关是独立进程，固定 origin 映射空间。开发环境使用回环 3182/3183/3184，正式域名与 HTTPS 尚不部署。不能由 Referer、全局公司 Cookie 或模型参数决定租户。
- 容器键为用户 UUID＋空间。独立持久化 home/workspace、非 root、network=none、只读代码与根文件系统，无宿主业务目录、Docker socket 或模型密钥。原生 Web 通过实例专属 Unix socket 接入；模型与部门工具走另一条绑定实例的 Unix socket，不能访问任意宿主 HTTP 服务。
- 网关每次请求/WS 帧检查原部门会话及当前授权，后台巡检断开已失效连接并停止实例。权限变更、下架/发布变更使运行实例失效，避免继续使用旧工具上下文；已收到的历史回答不宣称可追溯收回。
- 原生 RPC、mux endpoint、个人设置、文件路径均白名单校验。未知接口默认拒绝，平台 provider/预设/插件/权限配置不可写。模型调用只允许管理员配置的固定上游和模型，不提供通用 HTTP 代理；平台密钥只在网关进程。
- 部门工具按调用时权限读取正式表，技能仅来自启用的审核发布记录，绝不挂载旧文件型技能、草稿或审核表。共享由单独空间使用，不把两个公司的记录混入同一会话。
- 原生文件入口仅允许本人 workspace 内经过 realpath 验证的普通文件；拒绝符号链接逃逸、home 配置和任意绝对路径。技能资源按已发布记录 ID 与资源路径读取。
- 原生认证预检/续期在服务器完成；变更请求至多发送一次，不因未知网络结果自动重放。实例启动有明确状态、资源上限和超时，不常驻预启动全部用户。
- 对话创建时记录授权及资料版本指纹。版本变化后，旧记录可供本人查看，但不能续问、改队列或派生新对话；必须新建对话，防止将已撤权或下架资料继续送入模型上下文。

## 本阶段的产品范围

- 对话、允许的模型选择、语言、主题、字号、对话显示和发送偏好按「用户＋空间」分别保存。模型及供应商由系统管理员配置，普通成员不能编辑平台密钥。相同用户在另一登录设备打开同一空间会替换该空间的活动实例，但不会共用其他用户的数据。
- 保留新对话、历史对话、个人偏好、管理员允许的模型选择和部门工具。移除插件安装、运行权限切换、任意预设、宿主文件浏览、上传、Shell 和原生文件型技能等入口，避免绕开审核发布边界。此阶段不是完整开发者工作台；通用文件生成和上传工具还未开放。
- skills.use 表示可让 AI 读取并采用已发布技能说明及非脚本附件；读取 scripts/ 下的附件另需 skills.source_read，不允许直接执行任意脚本。知识目录和流程资料仍由原部门系统维护和审核。
- 原生下载只支持本人工作区的普通文件，强制附件下载；不在浏览器直接执行生成的 HTML。当前没有开放生成文件的通用工具。
- 开发版同时最多两个活动实例，每个 640 MiB／0.5 CPU，15 分钟空闲回收；首次启动可能需一至两分钟。额度满或内存不足时明确提示，不抢占现网资源。
- 初次通过本机 OpenAI-compatible 测试模型完成工具闭环；后续真实模型合成数据验收见下文。正式 HTTPS 域名、反向代理和生产容量尚未验收。

4. AI 入口的启动/错误/登录失效状态；接口、真实实例与浏览器验证。
5. 停止临时服务并核实现网不变，记录未通过项与部署前条件。

### 观测结果

| 边界 | 实测结果 | 意义 |
| --- | --- | --- |
| 会话列表 | B 能列出 A 的会话 | 需要服务端会话归属校验，不能只隐藏前端列表 |
| 会话操作 | B 能直接按 A 的 sessionId 修改标题 | 每一个读写、搜索、导出、分叉等入口都需要鉴权 |

| 文件下载 | B 能下载同一工作区内 A 的合成文件 | 仅限制“位于 workspace 内”不足以做多人文件隔离 |

### 决策与最小下一步

共享运行在技术上并非不可能，但完整保留原生 UI/会话/设置/文件/工具能力，需要跨 HTTP、WebSocket、持久化和工具上下文的租户适配。本轮已经出现多个独立阻断点，不值得直接进入大改。

当前优先方案是继续复用同一套代码/依赖，保留个人持久化目录，限制同时运行的实例数、空闲后停止、名额满时排队。用户数量不应等于常驻实例数量。去掉 Docker 而仍保留每人的完整 Node/Harness 进程，不会自动消除这些进程本身的内存开销。

下一轮最小验证可先只比较 1 个/2 个活跃实例与排队体验，再确定容量和空闲时间。不要把正在生成或有未完成工具任务的实例按简单“无 HTTP 请求”计时回收。磁盘方面，应先统计个人文件、日志、缓存、历史构建分别占用多少，再设配额和保留期；本轮没有删除用户资料或清理构建文件。

若后续用户规模确实超过有限实例池能力，再单独评估“共享聊天/检索服务 + 按任务隔离执行”的窄功能原型；是否保留完整 Harness 前端需另行决定，不能宣称已有无缝替代方案。

### 验证到的行为

1. A 占用名额，B/C 按进入顺序等待；同一用户的重复请求合并到一个队列位置，取消其中一个请求不会取消另一个。
2. 原生会话中确实存在排队消息时，回收器判为非空闲。
3. 没有浏览器连接时，流式模型仍在执行，超过 2 秒阈值后 A 不被回收，B 仍等待。
4. 模型转入阻塞的工具调用后，同样超过阈值，A 不被回收。
5. 模型回答、工具和后续排队消息完成后，确认持续空闲才停止 A，随后自动启动 B。
6. B 看不到 A 的会话，不继承 A 的中文语言设置。
7. 请求正在处理时的 lease 阻止回收；状态查询超时或返回未知结构时保留实例并重置空闲观察起点。
8. 排队请求取消后不创建容器；等待期间登录被撤销的用户无法获取运行名额。
9. A 再次进入时新建容器，但复用原个人目录：原会话 ID、完成回答标记、中文配置、授权版本绑定及合成工作文件均保留。
10. 探针运行名额上限保持为 1，结束后临时容器/目录删除、合成账号停用、会话及授权撤销。

### 回收判定与防竞态

探针同时检查：
- `session/list` 的 running 状态；
- `session/control` 基线中的待执行消息队列；
- 后台 jobs：running、stopping 和未知状态阻止回收，completed/killed/failed 视为终态；
- 正在处理的入口请求 lease。

只有这些检查均明确空闲并持续达到阈值才回收。计时起点取最近请求和首次确认空闲的较晚者，因此长任务结束后不会因“上次用户请求很久以前”而马上被停掉。

探针内所有任务提交通过与回收器相同的锁/lease，避免检查为空闲后恰好收到新任务的竞态。实际网关集成时必须让所有相关入口遵守同一规则；不能仅移植一个定时回收函数。

### 资源与体验

- 首次冷启动（含创建初始会话、设置）约 64.9 秒。
- 恢复后单实例快照：370.7 MiB / 640 MiB，CPU 18.88%，32 个容器任务/PIDs。
- 该快照发生在恢复和读取历史之后，不能当作稳定空闲 CPU、并发容量或峰值模型负载结论。
- 重新启动仍有等待成本。过短的正式空闲时间会造成频繁冷启动，2 秒仅用于测试，不应直接上线。

### 结论的适用边界和后续集成要求

本轮证明的是个人实例轮换和持久化机制，不是已经交付完整排队产品：
- 未改在线 /ready、启动页、排队提示、取消按钮或自动重连行为。
- 使用合成模型/工具，未进行外部模型并发压力测试；配置保留实测覆盖 locale，未穷举每个设置项。
- 受管 preset 未启用原生后台 jobs，因此 jobs 终态逻辑通过合成状态断言验证；真实长模型和工具调用已用原生 Harness 实测。
- 探针冷启动仍在 admission lock 内串行进行，适用于这次单名额验证。上线前需把启动移到可取消的后台任务，使冷启动不阻塞排队状态读取、撤权检查或其他活跃用户请求。
- 用户退出、权限撤销、管理员停用等主动安全撤销仍应沿用现有规则，与“空闲回收不能停任务”分开；不可用本探针的保守状态失败策略替换现有撤权处理。
- 未来允许 Shell/任意技能脚本或外部后台进程时，必须补充这类任务生命周期跟踪，不能只依据当前受管 preset 的验证结果。
- 下一步可在独立验收环境集成排队状态、取消等待、安全回收和重新唤醒，再做页面端验收；当前不推送、不切换现网。

正式端口 3080/3081 与验收 3181–3184 的监听 PID 保持不变，本轮没有重启这些服务。

## 2026-10-29 异常退出恢复补验设计
监督进程丢失内存名额后，不允许忽略遗留容器继续启动。网关lifespan在监听业务请求前调用Manager.recover。
只检查本持久化根目录namespace下、具有专用标签、精确个人目录绑定的容器。锁仍防止两个监督进程同时管理同一目录。
已退出容器可清理；运行中的旧容器必须通过原生session/control和session/list确认没有任务、队列及后台作业。
先验证全部候选，再清理已确认空闲容器；任何候选仍忙、探测失败或归属不匹配，启动失败且保留容器及所有持久资料。
不承诺进程崩溃中的模型请求自动续跑；已保存会话/配置恢复，进行中的任务若中断由用户检查后重试，不自动重复执行有副作用工具。
