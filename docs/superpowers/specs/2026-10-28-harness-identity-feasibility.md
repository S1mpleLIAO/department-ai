# Harness 多用户隔离与自动认证：技术验证记录

日期：2026-10-28。范围：阿里云上的隔离技术试验；不是生产登录/权限功能上线。

关联：[总体设计](2026-10-28-identity-permissions-review-design.md)、[实施计划](../plans/2026-10-28-identity-permissions-review.md)、[复现说明](../../../harness/tests/identity_probe/README.md)。

## 结论

**“用户 × 空间独立运行环境 + 部门系统代管 Harness 认证”的方向可行。** 已通过真实 Harness 实例验证会话隔离、个人设置隔离、跨实例 Cookie 拒绝、过期 Cookie 服务端再认证和 WebSocket 事件流。

这不等于 Harness 原生支持部门账号体系，也不等于已经完成安全的生产网关。当前生产仍是原共享实例。浏览器 iframe、真实登录会话、三空间域名、MCP 授权、AI 工具执行和完整管理接口限制仍需后续集成验证。

## 1. 环境与不干扰边界

- 复用已安装的 `dsh-v0.1.5-rc.1` 源码和前端产物，只读挂载；没有下载、重新安装依赖或重新构建。
- 复用服务器已有 Debian 系容器镜像 `pgvector/pgvector:0.8.6-pg17-bookworm`，覆盖入口为 Node。仅借用 OS 文件系统，**没有启动数据库**，不作为生产 AI 镜像方案。
- 每实例 UID/GID 10001；只读根文件系统/代码；去掉全部 capabilities；no-new-privileges；独立可写 home/workspace/tmp。
- `network=none`，不发布任何宿主端口；容器内部 Harness 监听 `127.0.0.1:39080`。测试请求通过 `docker exec` 发起。
- 每实例限制 640 MiB 内存、无额外 swap、0.5 CPU、128 PIDs；最多同时运行两个；启动前检查可用内存。
- 生产 `.env`、DSH home、部门技能、数据库卷、Docker socket 没有挂载进去。没有真实模型调用，没有复制历史对话或业务文件。
- 不修改 Nginx、DNS、证书、生产配置、业务代码或数据库，不重启生产进程，不提交/推送 Git。

试验实体：`alice-zkxk`、`bob-senyuan`、`alice-shared`。Alice/Bob 是测试身份，空间归属由试验端映射，不是客户端提交任意 user ID 后直接信任。

## 2. 已取得的真实运行证据

| 验证项 | 结果 | 证据与边界 |
|---|---|---|
| 匿名访问 | 通过 | 根页面 401；没有关闭原生认证 |
| 服务端换取 Cookie | 通过 | token 入口 303 + Set-Cookie；带 Cookie 页面 200；未把凭据输出给浏览器 |
| 错误启动 token | 通过 | 401 |
| 跨用户实例 Cookie | 通过 | A 的 Cookie 在 B 返回 401 |
| 会话隔离 | 通过 | 调用真实 `session/create`、`rename`、`list`；A/B 各只列出自己的一个持久化会话 |
| 个人设置隔离 | 通过 | 真实 `settings/update` 分别写 locale=zh/en，分别持久化在独立 home；未实际调用付费模型 |
| 同用户两空间 | 通过 | Alice 的 shared 与 zkxk 分别路由到独立实例，会话 ID 不互相出现；不是浏览器多标签页测试 |
| 自有文件下载 | 通过 | 原生 `/api/file` 下载本人工作区测试文件，200 且内容正确 |
| 宿主与跨 home 访问 | 通过 | 文件系统读取宿主 `.env` 为 EACCES、另一 home 为 ENOENT；原生下载宿主路径返回 400，未返回文件 |
| 代码只读 | 通过 | 容器内写只读挂载文件返回 EROFS |
| 宿主数据库/部门 API | 通过 | 容器内回环 5432/3081 拒绝连接，172.17.0.1:5432 网络不可达；Docker socket 不存在 |
| 真正过期的 Cookie | 通过 | 使用临时 home 密钥签名的已过期 Cookie 返回 401；不是只测试乱码 Cookie |
| 自动认证恢复 | 通过 | 试验 broker 检测 401、用私有 token 换新 Cookie，再向真实 Harness 创建会话；变更只发送一次 |
| 无身份/越空间/管理 RPC | 有限通过 | 试验 broker 拒绝；尚非真实 HTTP 网关、中间件或完整 RBAC 验收 |
| WebSocket | 通过 | 无 Cookie 返回 401；服务端注入 Cookie 后 101，`/api/remote.mux` 的 `$events` 返回 ready，5.5 秒内收到 2 次 ping |
| 重启后的数据/认证 | 通过 | 临时实例新 token 生效、旧 token 401；旧合法 Cookie 仍 200；原会话与设置保留；broker 能用新 token 再认证 |

试验 broker 允许的 RPC 仅 `session/create`、`session/list`、`session/rename`；其余默认拒绝。这只是试验白名单，不是正式产品完整接口清单。下游错误后不会自动重放写操作；断线、并发续期、上传与长任务的幂等保障尚未验收。

## 3. 实测发现的安全缺口

**原生 `/api/file?path=/home/probe/dsh/.credentials.yaml` 对已认证调用返回 200。** 两个临时实例均复现。没有读取生产凭据，日志没有打印测试凭据内容。

因此：

1. 只做页面登录和隐藏按钮不能解决授权问题。原生 Harness 的认证代表实例访问权，不能代表“部门普通成员权限”。
2. 正式下载应改为有所有权检查的文件句柄/产物 ID，解析符号链接和路径后验证归属，禁止任意绝对路径。会话导出、上传、预览也要纳入检查。
3. 设置/凭据/插件/预设/权限策略不能全量透传给普通成员。真实 `settings/describe` 可见命名空间包括 `agent-default-model`、`llm-deepseek`、`llm-pi-ai`、`agent-presets`、`shell`、`permission` 等。
4. 网关需要同时验证 HTTP 和每个 WebSocket mux 帧；不能只允许一个 `/api/remote.mux` URL 就认为里面的方法安全。
5. 模型/API 管理凭据、启动凭据和服务授权不能成为代理工具可随意读取的文件。生产要设计更窄的运行配置、文件系统暴露面、服务端模型出口和 MCP 授权；网关过滤不能替代工具侧隔离。
6. 本次 `network=none` 证明了隔离底线。生产要开放模型/MCP 网络时，必须重新证明不能访问数据库、其他实例、宿主管理接口及未经允许的服务。

这次验证不是容器逃逸审计，也未证明复杂 shell/文档工具在嵌套 sandbox 下均能工作。

## 4. 资源与部署可行性

在 0.5 CPU、640 MiB 上限、源码 tsx 启动条件下：

- 首两个实例冷启动约 68.37 秒、67.35 秒；Alice/shared 约 67.27 秒。
- 两实例空闲同时运行快照：391.2 MiB、392 MiB；CPU 0.25%、0.21%。不是峰值，也不是模型请求/文件处理负载数据。
- 服务器约 7.1 GiB 总内存，验证前可用约 1.5–1.6 GiB，正在运行其他较重服务。

**不宜给所有成员和三个空间预先常驻实例。** 推荐先实现按需启动、空闲停止但保留 home，初期限制少量同时活跃实例，再做真实模型/文档负载测量；不把“测试时两个空闲实例能运行”当作多人正式容量承诺。独立 home 必须持久化，清理实例不等于清理用户数据。

准备阶段遇到两个启动问题：直接执行构建入口缺少 monorepo 动态解析配置；源码启动需要 `--expose-internals`。最终复用 tsx 和必需 Node 参数。早期有一次 exec 进程退出 137，但没有足够证据证明是 OOM，不能据此判断生产内存故障。

## 5. 正式自动认证契约

推荐链路：

```text
浏览器的部门登录会话
  → 部门 AI 网关：验证会话、公司空间、AI 使用权限
  → (user_id, space_id) 对应的私有实例
  → 网关私有 token / Cookie → Harness
```

- 浏览器不再手工打开带 Harness token 的链接；token 和上游 Cookie 保留在服务器。
- 浏览器无效登录返回部门登录流程；Harness 401 由网关处理，不直接展示原生英文错误。
- 网关启动/重启实例时安全获取本轮启动 token，并绑定实例代次。生产方案不能靠公开日志接口取 token。
- 续期先做无副作用探测/换 Cookie；提交变更最多一次；网络结果不明时不盲目重复上传/执行/创建。
- 用户退出、停用、公司权限撤销后，网关撤销入口并主动关闭对应 WebSocket/长连接；不能只等待 Harness 的 30 天 Cookie 到期。
- 上游 Host/Origin 固定为所属实例的正确 authority；外部 Origin/CSRF 由网关按真实浏览器来源验证。不能信任客户端伪造的身份头。
- 私有实例仅允许网关访问；当前直接转发共享 3080 的入口届时需统一收口，不能留下绕过路径。

本次 Broker 只是内存测试适配器，使用 `docker exec` 运输请求，**尚未实现以上生产网关**。

## 6. 后续验收门槛

核心可行性成立，可以继续身份/公司/权限数据契约设计。AI 对普通成员开放之前仍需：

- 真实登录 + HTTPS + iframe + 多标签页/多空间 origin 的浏览器验证；尚未改正式 DNS/证书。
- 模型目录与个人模型偏好白名单，管理 RPC 与 mux 帧限制；未知接口默认拒绝。
- MCP 请求身份绑定、授权变更/撤销、文件句柄和检索空间过滤的真实端到端测试。
- AI shell/文件/技能工具不能绕过公司授权；生产模型出口网络策略与文档工具验证。
- 并发续期、服务重启中写请求、上传/执行幂等、长回答流、退出断连和容量测试。

原计划阶段 0 不应整体打勾。本次完成核心技术可行性，后续网关集成和安全验收仍是独立交付项。
