# 知识适用范围与上下文检索设计

日期：2026-09-03  
状态：待用户书面复核

## 背景与目标

当前系统已经区分“生成模板”“参考知识”“模板＋参考知识”，也保存自由文本的适用场景，但知识入库不能真正关联业务流程步骤，模板和知识检索也没有接收当前工作上下文。

本次改造让一份知识资产可以声明它主要在什么工作环境中使用，并让 AI 在检索时优先选择与当前环境匹配的真实知识，同时保留全库语义检索作为兜底。

知识适用范围分为三类：

1. `global`：全局通用，不依赖特定工作。
2. `task`：独立任务场景，例如编写设计方案、制作汇报材料。
3. `process`：业务流程中的具体步骤，例如项目采购 / 采购合同。

本次不实现人员、部门、角色或文档访问权限。

## 已确认的业务规则

1. 知识不强制关联业务流程。
2. 重复、稳定并具有明确阶段的工作使用“业务流程步骤”。
3. 一次性交付且不需要完整流程的工作使用“独立任务场景”。
4. 制度、公司介绍、通用参数等可以选择“全局通用”。
5. 流程和场景关联只提高检索优先级，不作为硬过滤条件。
6. AI 可以建议适用范围，但必须由用户在入库前确认。
7. 一份知识资产只保存一份；本阶段只维护一个主要适用范围，不实现多流程、多步骤关联。
8. 文档用途与适用范围相互独立：用途决定如何建立索引，适用范围决定在什么工作上下文中优先使用。

## 最小数据模型

不新增数据库表或列，复用 `knowledge_documents` 已有字段：

- `applicable_process_id`
- `applicable_step_id`
- `applicable_scenario`

API 增加派生字段 `scopeType`，取值为 `global | task | process`。保存规则如下：

| `scopeType` | `applicableProcessId` | `applicableStepId` | `applicableScenario` |
|---|---|---|---|
| `global` | 空 | 空 | 空 |
| `task` | 空 | 空 | 必填的任务场景名称 |
| `process` | 必填 | 必填 | 可选的补充场景说明 |

后端必须验证：

- `task` 必须填写非空 `applicableScenario`。
- `process` 的流程和步骤必须存在，且步骤必须属于所选流程。
- `global` 保存时清空其他适用范围字段。
- `task` 保存时清空流程和步骤字段。
- `process` 不接受缺少流程或步骤的半关联状态。

历史文档按已有数据派生：存在流程与步骤时为 `process`；否则存在适用场景时为 `task`；其余为 `global`。

## 入库与编辑体验

知识入库第二步“确认文档属性”增加“适用范围”单选项：

- 全局通用
- 独立任务场景
- 业务流程步骤

选择“独立任务场景”时显示任务场景文本框；选择“业务流程步骤”时显示流程和步骤下拉框，步骤跟随流程联动；选择“全局通用”时不显示附加字段。

AI 元数据分析响应增加：

- `suggestedScopeType`
- `applicableProcessId`
- `applicableStepId`

分析请求向模型提供当前真实流程及步骤列表。模型只能返回列表中存在的流程和步骤；无法可靠判断时建议 `task` 或 `global`，不能虚构流程 ID。AI 建议只预填表单，仍由用户点击“确认属性并继续”。

文档详情和编辑弹窗展示相同的适用范围控件。最终入库确认页显示“全局通用”、任务场景名称，或“流程名称 / 步骤名称”。

## 检索上下文与选择逻辑

模板检索和参考知识检索增加可选上下文：

- `processId`
- `stepId`
- `taskScenario`

调用方一次只能提供流程步骤上下文或独立任务场景上下文。完全不提供时保持现有全库检索行为。

检索顺序为：

1. 使用现有向量召回和关键词召回获取语义候选。
2. 补充直接关联当前流程步骤或任务场景的有效候选，避免关联知识因召回窗口过小而遗漏。
3. 使用现有 Rerank 模型计算内容相关性。
4. 在相关性阈值通过后，根据上下文匹配级别进行软排序：当前步骤直接关联最高，同流程关联次之；独立任务场景直接匹配最高；全局知识获得轻微兜底优先级；其余候选仍可返回。
5. 保留现有版本去重，只推荐同一模板家族和变体的最新有效版本。

响应为每项结果增加：

- `contextMatch`：`exact | same-process | global | semantic`
- `selectionReason`：供 AI 向用户解释推荐原因的简短中文文本

`score` 保持 Rerank 原始相关性分数，不能用上下文加权后的值冒充模型分数。

## MCP 与 AI 行为

`template_search` 和 `knowledge_search` MCP 工具增加相同的可选上下文参数。工具描述明确要求：

1. 先判断用户任务是否属于真实业务流程。
2. 属于流程时先调用 `process_list` 确认流程和步骤，再携带真实 ID 检索。
3. 不属于流程但目标是一次性交付时，传入简短、稳定的 `task_scenario`，例如“编写设计方案”。
4. 普通知识问答可以不传上下文。
5. 向用户推荐模板时说明 `selectionReason`，由用户确认后再读取完整模板。

后端不增加额外大模型调用来识别任务类型；任务判断继续由正在对话的 Harness AI 完成，避免重复调用、增加延迟和产生两个模型判断不一致的问题。

## 模块边界

后端继续使用现有业务域：

- `documents/schemas.py`：适用范围输入契约。
- `documents/store.py`：保存、更新和映射适用范围。
- `documents/router.py`：调用流程关联校验并组装文档。
- `documents/service.py`：AI 元数据建议字段和提示词。
- `processes/store.py`：提供流程步骤存在性校验。
- `search/schemas.py`：检索上下文输入契约。
- `search/store.py`：补充范围关联候选。
- `search/service.py`：候选合并、软排序和推荐原因。
- `mcp_server.py`：向 Harness 暴露上下文参数和调用说明。

前端继续位于 `frontend/js/features/knowledge/`：

- `upload-metadata.js`：适用范围控件、AI 建议应用、收集和校验。
- `upload.js`：向元数据组件提供流程状态，并在最终确认中展示范围。
- `documents.js`：详情展示和编辑适用范围。

不修改 `backend/app/main.py` 和 `frontend/js/main.js` 的职责，不创建新的共享模块，不新增依赖。

## 错误与兼容

- 流程或步骤已被删除：保存返回明确的 404/400 错误，前端停留在属性确认页面。
- 流程选择变化：立即清空原步骤，避免提交不属于该流程的步骤。
- AI 返回不存在的流程或步骤：忽略无效关联，保留其他元数据建议，并要求用户手工确认适用范围。
- 检索传入无效流程上下文：拒绝请求并给出明确错误，不静默转换成全局检索。
- 旧客户端未发送 `scopeType`：按 `global` 处理，保持兼容。
- 删除现有启动迁移中每次清空流程关联字段的语句，避免新关联在重启后丢失。

## 测试与验收

### 后端自动检查

- 三种适用范围的 schema 校验和字段归一化。
- 流程步骤必须存在且归属正确。
- 保存、读取、编辑后适用范围不丢失，服务重启不再清空关联。
- AI 元数据建议只接受真实流程步骤 ID。
- 无上下文检索保持原行为。
- 流程直接关联、同流程、全局和纯语义候选的软排序正确。
- 独立任务场景关联知识优先，但未关联的高相关候选仍可返回。
- MCP 工具参数与 REST 检索参数一致。

### 前端自动检查

- 三种适用范围切换只显示对应字段。
- 流程切换会重置步骤。
- AI 建议不会跳过人工确认，且无效流程建议不会写入表单。
- 手工入库提交正确范围字段。
- 文档详情和编辑正确显示三种范围。

### 浏览器验收

1. 上传一个设计方案模板，选择“独立任务场景 / 编写设计方案”，完成入库。
2. 上传一个采购合同模板，选择“业务流程步骤 / 项目采购 / 采购合同”，完成入库。
3. 上传公司通用介绍，选择“全局通用”，完成入库。
4. 在 AI 助手中分别发起设计方案、采购合同和普通问答任务，确认推荐顺序和理由符合上下文。
5. 确认没有权限相关界面、接口或数据库变更。

## 不在本次范围

- 人员、角色、部门和文档访问权限。
- 一份文档关联多个流程、步骤或任务场景。
- 可配置的任务场景字典或单独的任务场景管理页面。
- 新增任务中心页面。
- 自动执行流程状态机或保存用户任务进度。
- 修改向量模型、Rerank 模型或向量维度。
