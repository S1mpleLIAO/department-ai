# 独立验收环境：原生个人模型与固定模式

2026-10-30 用户授权接入当前独立验收环境；不修改现网或上游 Harness 源码。

- 原生“设置 → 模型”维护个人服务、API Key、模型列表；不用部门系统额外页面。
- 同一账号在不同公司空间仍是不同运行目录、会话、凭据；部门受管模型继续可用但不可在个人设置改写。
- 新会话选择部门助手或标准模式（通用编程）；已开始的会话保留原模式。
- 只开放两个平台预设，不允许通过预设管理安装插件或改变权限边界。默认模式可在原生设置选择。
- 通用编程沿用原生 workspace-write 沙箱和审批策略；容器仍无外网、只读系统、非 root、无 capabilities，只挂载自己的持久化目录和公共只读程序。
- 个人模型请求通过仅支持模型列表及推理接口的出口，使用自己的密钥。解析 DNS 后拒绝私网/回环/元数据地址，连接检查后的 IP，TLS 校验原域名，拒绝重定向。通用网络命令和依赖下载不因此获得外网权限。
- 部门工具在每次调用时重新校验人员、空间和已发布资料权限。已有会话授权版本检查保留。
- 空闲回收只停止实例，不删个人 home；并发上限、排队、任务保护沿用原实现。

## 兼容和验证

固定 dsh-v0.1.5-rc.1；模型使用原生 llm-pi-ai、credentials、settings。HTTP 客户端当前是 httpx 0.28/httpcore 1.0，DNS 固定连接适配在 personal_models.py，升级需重验该适配。

自动化入口：backend/tests/assistant_personalization_check.py、assistant_personalization_live.py、assistant_personalization_browser.mjs。真实浏览器证据保存于私有 .identity-state/personalization-live，仅最终测试结果与不含密钥的截图可分享。测试凭据不提交 Git。

上游 checkout 缺少 landlock-run 预编译产物。先运行 `python3 deploy/identity/build-native-sandbox.py`，只在验收 checkout 构建同版本原生 C 源码；固定容器配方只读挂载该产物，然后运行现有 prepare-acceptance-host.py 更新固定启动配方。没有关闭 Harness 沙箱或审批。宿主较旧内核报告 Landlock partial，容器仍保留只读根目录、无网络和独立 home。
