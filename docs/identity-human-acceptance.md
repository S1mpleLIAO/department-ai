## 入口与连接

入口：http://127.0.0.1:3181/department

在Mac终端建立SSH转发并保持终端开启：

```sh
ssh -N -o ExitOnForwardFailure=yes \
  -L 3181:127.0.0.1:3181 \
  -L 3182:127.0.0.1:3182 \
  -L 3183:127.0.0.1:3183 \
  -L 3184:127.0.0.1:3184 aliyun
```

如果原来的3181转发已经打开，保留它，只在另一终端补充AI的三个端口：

```sh
ssh -N -o ExitOnForwardFailure=yes \
  -L 3182:127.0.0.1:3182 \
  -L 3183:127.0.0.1:3183 \
  -L 3184:127.0.0.1:3184 aliyun
```

从部门系统中的“AI助手”进入，系统自动完成Harness认证，不需要手工复制token链接。请使用127.0.0.1，不要混用localhost。此入口尚不是正式公网HTTPS部署。

## 推荐人工验收顺序

1. **先准备审核员**：分别登录zkxk-reviewer、senyuan-reviewer，修改初始密码后退出。
2. **成员提交**：登录zkxk-member，在中科信控新增一条名称带“验收-”的流程、文档或技能，保存草稿并提交。确认不能直接发布，也不能编辑他人的已发布内容。
3. **退回与重新提交**：用zkxk-reviewer退回，填写原因；成员修改自己的退回内容，再提交。待审内容不应出现在AI可用资料中。
4. **审核发布**：审核员通过并点击发布；成员刷新后可看到已发布内容。审核员不能审核自己的提交。
5. **已有资料修改**：用department-manager创建已有资料的修改送审；发布前仍使用原版本，由对应公司的审核员审核发布后才切换到新版本。建议先用新建的验收资料做这一步。
6. **公司隔离**：用senyuan-member确认只能看到森远股份和部门共享；看不到中科信控合同、流程与报销技能。用department-manager验证可以切换两家公司。
7. **只读与AI**：用zkxk-reader确认没有新增/审核功能，不能下载技能脚本源码，但可进入AI助手查询已发布的报销技能说明。可提问：“请列出当前可用技能，并概述报销材料需要哪些输入。”
8. **下架生效**：用department-manager下架一条新建的验收资料，确认新AI对话不再获得它；受资料版本变化影响的旧对话只能查看历史，继续提问需要新建对话。
9. **审计与账号**：用liao-admin查看操作记录，核对提交人、审核人、发布与授权变更。可调整验收权限组后，用相应账号重新验证。

测试多用户时使用不同浏览器、独立浏览器配置或普通/隐身窗口；同一浏览器的普通窗口共享登录Cookie，不能当成两个独立用户。

记录问题时提供：账号、公司空间、具体步骤、预期结果、实际结果及截图。不要截图或粘贴密码、模型密钥。

## AI范围与运行说明

AI现已在3181验收页面启用，使用独立个人目录和现有deepseek-v4-flash配置。个人运行数据位于 /root/liao/identity-ai-acceptance，不共用生产Harness目录，也不使用会被清理的/tmp作为本轮持久目录。

当前最多同时运行4个个人AI实例，上限可配置。名额满或服务器可用内存不足时，新请求进入排队；同一账号、同一空间不会重复占排队位置。一个账号同时使用不同公司空间，会分别占用实例名额。首次启动可能需要1–2分钟。

空闲15分钟后自动回收运行实例，个人会话、配置和工作区文件保留；再次打开时按需恢复。有运行中任务、待执行任务、未结束后台作业，或无法可靠判断任务状态时，不执行空闲回收。主动退出登录或权限撤销会终止访问，不属于空闲回收规则。

可选的容量人工检查：用独立浏览器会话依次打开4个验收账号的AI助手，第5个应显示排队及取消入口；前一个空闲回收或退出后，等待者获得名额。如果当时内存不足，可能在未达到4个时提前排队，这是预留服务器内存的保护行为。

此阶段AI能够读取并采用已发布技能说明/允许资源，尚未开放任意Shell或自动执行报销脚本，也没有新增上传下载工作流。网页源码权限与AI scripts/读取权限一致，均需要skills.source_read。
