# 已有资料修改审核（独立环境）

用户于 2026-10-28 授权继续实现，不部署现网。沿用 identity-access-20261028 工作区。

## 独立契约设计

- 在流程、知识文档、技能的原有编辑入口发起“修改送审”。需要所在空间的模块查看和 edit_any 权限；不扩大普通成员默认授权。
- 服务端读取正式资料，生成私有修改稿和基准快照；客户端不能自行指定基准内容。原 ID、创建者和正式资料保持不变。
- 复用现有草稿、不可变提交、驳回、通过和发布状态机。修改稿的保存及提交均不写正式资料。
- 新增迁移 003：提交表保存 target_id、base_token、base_payload；每次提交版本也保留基准快照。
- 新 API POST /api/reviews/edits：kind、targetId、幂等 id；返回修改稿详情。现有 PUT/submit/approve/publish 接口按 target_id 区分新增与修改。
- 审核详情同时展示“修改前”和“本次修改稿”。版本冲突不自动合并，也不允许用旧审核覆盖新正式版本；从正式资料重新起草，旧稿保留供对照。
- 发布时锁定正式记录并比较基准标识和内容，包含归档/停用变化；失败保留原正式内容、索引、附件及审核记录。
- 流程更新保留流程 ID。知识编辑覆盖元数据、用途和人工分块，保留原文件；目录调整不生成向量，普通元数据变化只更新文档向量，分块/用途变化才更新正文索引。
- 本阶段不新增知识原文件替换操作，沿用现有编辑能力；新原文件仍走上传流程。
- 技能正文与附件整体审核，发布后同名正式记录原子替换。旧文件型技能首次修改发布转为数据库记录，旧文件保留但不再覆盖数据库版本；受控文件写接口与发布使用同空间技能锁。
- 保留已有显式 publish_direct 后端管理接口；业务页面修改统一送审，不新增绕过审核入口。
- Harness 加载已发布技能、正式迁移部署不在本阶段。

## 实施与验收

1. 增量迁移及服务端基准快照、幂等起草、权限和发布冲突校验。
2. 三类正式资料更新与索引最小更新策略；文件型技能并发保护。
3. 复用现有编辑表单及审核中心，增加前后对照和明确的冲突恢复提示。
4. 阿里云隔离数据库测试三类修改、驳回重提、并发/直接修改冲突、失败重试、撤权与跨公司拒绝；前端交互和真实浏览器验收。
5. 关闭临时服务，核对现网进程及健康状态；不合并、不提交、不推送。
