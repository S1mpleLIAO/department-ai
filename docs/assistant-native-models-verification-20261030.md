# Harness 原生个人模型设置最小验证

日期：2026-10-30。范围：独立 identity-access-20261028 工作区，临时账号、测试数据库和临时个人实例。没有新增个人模型配置页面，没有修改或重启正式服务、现有验收服务。

## 结论

当前安装的 dsh-v0.1.5-rc.1 已具备原生“设置 → 模型”界面。可以继续使用部门系统统一登录、个人实例和独立 DSH_HOME，让用户在原生页面管理个人提供方、密钥和模型。无需为了这项能力升级 Harness 或引入另一套登录系统。

本轮是可行性验证，未部署到现有验收账号。临时测试进程启用了原生模型设置插件，并对指定测试提供方开放必要的配置、凭据、模型发现与选择接口；产品网关和运行策略仍保持原状。

## 实测结果

两个临时账号分别属于中科信控、森远股份，各自只有本空间的 assistant.use 权限。所有项目执行和浏览器测试均在阿里云进行。

| 检查 | 结果 |
| --- | --- |
| 在原生 Settings → Models → Add a custom provider 添加提供方 | 两账号均成功；无额外配置页面 |
| 两人使用同一 provider ID `native-probe` | 分别显示 `Private ZKXK`、`Private SENYUAN`，互不覆盖 |
| 原生界面填写各自 API Key 并获取模型列表 | 均获取 `probe-fast`、`probe-reason` |
| 在原生输入框切换两种模型并发送消息 | 两账号均成功；服务端核对请求模型和对应账号密钥 |
| 乙账号使用甲账号密钥调用模型发现 | 测试提供方拒绝，401 |
| 跨账号向另一会话发送消息 | 网关拒绝，409，不执行消息 |
| 将甲账号登录凭据用于另一公司入口 | 拒绝，401 |
| 原生 credentials/describe 查询 | 不返回所填写的明文密钥 |
| 空闲回收并重新创建个人实例 | 两账号均成功；使用原个人持久目录 |
| 重启后原生设置页 | 提供方保留，仅显示本人配置 |
| 重启后原会话 | session ID 和两轮历史保留；甲保留 probe-reason，乙保留 probe-fast |
| 不重新填写密钥，再从原会话发送消息 | 两账号均成功，第三轮回复与选中模型相符 |
| 服务端密钥文件检查 | 密钥已持久化；包含密钥的 YAML 文件无组/其他用户权限 |

## 验证方法与证据

服务夹具：`backend/tests/assistant_native_models_probe.py`。
重启后的浏览器断言：`backend/tests/assistant_native_models_after_restart.mjs`。

第一阶段通过服务器上的 Playwright Chromium 操作原生页面完成：确认首次欢迎提示、添加同名提供方、填写不同密钥、获取并选择两种模型、创建个人工作区会话、切换模型、发送消息。没有用直接写配置文件替代用户添加模型的步骤。

第二阶段执行真实 `Manager.reap_once()`：先确认无活动任务，再把测试实例空闲时间推进到阈值之外，停止旧容器，从相同个人目录重新创建容器。随后自动检查原生设置页面、原会话、模型选择及再次调用。测试并不要求等待实际空闲阈值分钟数。

乙账号第一次重启观察时浏览器请求被测试控制端关闭，未将这次未收到响应的操作算作通过；重新完整执行回收、重启并取得成功响应后才记录通过。

本次保留的无密钥证据位于工作区 `.identity-state/native-models-probe/`：

- `browser-results.json`：隔离、两次回收及重启后断言结果。
- `server-results.json`：账号、公司、模型及密钥匹配结果，不记录密钥。
- `native-settings-zkxk.png`、`native-settings-senyuan.png`：重启后的原生提供方列表。

测试结束已停止本轮临时实例，撤销测试登录、停用临时账号并移除临时授权；浏览器凭据输入文件和临时个人目录已删除。原有验收个人实例仍运行。

正式 3080/3081 的 PID 保持 3455124/3455105；验收 3181 的 PID 保持 1892079，3182–3184 保持 1892080。未重启这些服务，也未操作原有会话和用户文件。

## 边界及后续接入

模型服务使用带每账号独立密钥的受控 OpenAI-compatible 测试接口。实际走过 Harness 原生模型发现、密钥存储、模型选择及流式回复链路，但不是商业模型能力或第三方服务兼容性测试。本轮只验证 openai-completions 协议；未验证 Anthropic、Responses、OAuth 或任意公网服务地址。

正式接入仍需把实验中的必要能力收敛为产品策略：

1. 对个人实例启用原生模型设置；允许个人模型配置及凭据操作，不开放其他宿主配置权限。
2. 配置、凭据和模型目录始终按登录用户及空间解析，保留公司授权、会话隔离及已发布资料过滤。
3. 现有隔离容器没有直接公网网络。本轮通过限定测试地址的私有中继验证调用；真实自定义服务还需要受控外连代理及敏感内部地址限制，不能简单开放容器网络。
4. 补齐原生提供方编辑/删除、密钥更新/删除、错误重试等完整操作测试，再在独立验收环境开放。

发现的新账号首次欢迎提示写入 `ui-onboarding` 曾被原策略阻止，本轮仅在临时夹具中精确放行该确认动作。最终正式接入时需一并处理。
