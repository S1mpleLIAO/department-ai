# 新增资料审核发布阶段

后续阶段已实现已有资料修改审核，见 [修改审核交付记录](review-editing-stage.md)。下文保留新增阶段当时的范围与验收记录。

仅在 identity-access-20261028 独立工作区实施；生产数据库、文件、3080/3081 和 Nginx 不变。

## 数据与权限契约

- 本阶段覆盖新建流程、上传知识文档和新建技能。已有正式资料的修改仍使用明确的直接发布权限，不暗中改变旧版。
- 普通成员保存草稿后在“提交与审核”查看、编辑并提交；草稿只对作者和本空间对应模块审核员可见。
- 提交生成不可变版本；待审核期间禁止编辑。驳回必须填写原因，作者修改后重新提交生成新版本。
- 审核与发布分两步：“通过审核”后“发布”；审核员不能审核自己的提交，包括超级管理员。
- 每个模块独立配置“审核新增”和“发布已审核”权限。发布不需要额外授予编辑正式资料或直接发布权限。
- 审核权限不跨公司；所有请求继续使用会话身份、空间授权、CSRF、Origin 和数据库 RLS。
- 未发布内容不写正式流程、知识文档/向量或可用技能列表，不能被检索。审核状态不能由客户端填写。
- 发布使用提交版本而不是可变草稿。发布失败保留审核结果，可重试；重复发布返回已发布结果。
- 行锁与修订号防止过期审核、多次点击及并发发布。文档生成向量成功后与正式数据在同一数据库事务提交。
- 新技能的正文和附件采用数据库发布记录，避免文件系统成功、数据库失败时提前泄露未发布内容。
- 本阶段只审核新增内容；审核发布的技能正文/附件保留原版本，可查看、下载、停用，
  不允许旧的文件编辑接口覆盖它。技能修改版本的审核和 Harness 加载发布记录在后续阶段接入。
- 文件下载按提交身份及公司授权检查，审阅不自动运行技能脚本。原文/提交版本保留备查。

## 接口与界面

- /api/reviews：当前空间分页列表（我的提交/待我审核/全部可见）、新建草稿。
- /api/reviews/{id}：查看及带 revision 更新草稿。
- /api/reviews/{id}/{submit|reject|approve|publish}：显式状态转换。
- /api/reviews/{id}/source：受控原文下载。
- 新增“提交与审核”页面，复用原生表单、现有弹窗/确认/错误提示；列表每页20条，筛选后页码归零。
- 复用现有新建流程、技能及上传向导；普通成员保存后提示“草稿已保存”，不能显示“已发布/已建立索引”。

## 验证要求

在隔离 PostgreSQL 中验证三类新增端到端、驳回重提、作者/跨公司/伪造状态拒绝、
提交快照不可变、正式检索隔离、发布失败重试、重复发布及权限撤销。
前端检查成员新增入口、草稿保存文案、编辑与状态按钮、失败保留内容以及审核弹窗。
Harness 身份网关和正式部署仍不在本阶段。
